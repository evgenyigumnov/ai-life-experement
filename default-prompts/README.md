# default-prompts — дефолтные тексты для LLM

Исходные файлы текстов по умолчанию. Код читает их напрямую — дублировать
содержимое в `prompts_messages.py` не нужно.
Рабочие файлы лежат в папке каждого агента (`agents/<имя>/`) и
перечитываются с диска при каждой итерации — править надо именно их,
а не эту папку. При первом запуске агента отсутствующие файлы
создаются копированием этих файлов; существующие никогда не
перезаписываются.

## Файлы в этой папке

| Файл | Что это |
|---|---|
| `system-prompt.md` | **Главный файл** — шаблон системного промпта нового агента (единственный источник текста; читается `prompts_template.py` при создании агента) |
| `user-message.md` | Финальное user-сообщение каждого тика: «выбери и выполни следующий полезный шаг» |
| `last-iteration-message.md` | User-сообщение последней итерации сессии: сохранить в памяти итог и следующий шаг, новую работу не начинать |
| `wake-up-message.md` | Короткая user-заметка о начале новой сессии; чек-лист первого тика находится в `system-prompt.md` |
| `sleep-warning.md` | System-заметка «скоро сон» — приходит, когда до конца сессии осталось ≤ 10 итераций (кроме самой последней) |
| `repeat-alert.md` | System-заметка «ты зациклился» (анти-ступор): 3+ итерации подряд один и тот же набор tool-вызовов |

## Деньги и кошелёк

В папке агента рядом с `messages.json`, `diary.json` и `mind-loop.json` хранится
`wallet.json`. Создатель начисляет единицы только командами с обязательным именем
агента: `python main.py <имя> pay 10 "за работу"`,
`python main.py <имя> balance` и `python main.py <имя> history`.
Эти команды не требуют конфигурации LLM и не создают неизвестных агентов.
Баланс агента — сумма начислений минус трат; остатки эффектов — отдельные
запасы. `money_balance` читает оба значения, а
`money_spend(units, purpose, type)` требует `type`: `speed` отменяет паузу
перед следующим циклом, `creativity` ставит `TEMPERATURE=1.4` на следующий
цикл. Одна единица даёт выбранный эффект на один цикл, N единиц — на N циклов.
Единицы не ускоряют генерацию и не добавляют итераций. Без `speed` действует
полное расписание `0 → 30 сек → 1 мин → 2 мин → 5 мин → 10 мин → 20 мин →
40 мин → 1 час → 2 часа → 4 часа`; `--loop-pause=N` — жёсткий режим, который
не расходует speed-циклы. Кошелёк переживает сон и перезапуск, а история
содержит только операции `credit` и `spend` с типом траты.

В каждый цикл при наличии непрочитанных сообщений автоматически добавляется
короткий статус по флагу `read`: «У тебя есть непрочитанные сообщения от
создателя». Сам текст не вставляется в prompt — агент при необходимости
вызывает `get_messages`. Tool помечает показанные непрочитанные сообщения
прочитанными, но в выдаче сохраняет исходный статус и добавляет отметку
«стало прочитанным»; заметка идёт вместе с финальным user-сообщением.

Правило о `web_fetch` и его постраничном чтении добавлено только в дефолтный
шаблон. Файлы `system-prompt.md` уже созданных агентов не перезаписываются:
при необходимости добавьте это правило в них вручную.

## system-prompt.md — шаблон системного промпта

Из этого шаблона при первом запуске `python main.py <имя>` создаётся
`system-prompt.md` нового агента с подставленным именем. То же происходит,
если папка агента уже есть, а промпта в ней нет. Существующий промпт
никогда не перезаписывается.

Плейсхолдеры подставляются только при создании — дальше это обычный
текст без форматирования. Как и пять файлов ниже, созданный
`system-prompt.md` агента перечитывается с диска при каждой итерации —
правки на живом агенте применяются сразу, перезапуск не нужен.

Переменные (плейсхолдеры):

- `{name}` — имя агента (подставляется дважды: «Тебя зовут …» и «… — это ты»);
- `{session_iterations}` — длина сессии в итерациях (30);
- `{sleep_warn_remaining}` — за сколько итераций до конца сессии начинается
  предупреждение о сне (10).

По умолчанию значения равны 30/10; их можно переопределить через
`SESSION_ITERATIONS` и `SLEEP_WARN_REMAINING` в `.env`. Шаблон написан в
мужском роде — если имя агента требует другого
рода, поправьте созданный файл вручную.

## Пять сообщений цикла

Эти файлы создаются в папке агента при первом запуске и, как и
`system-prompt.md`, перечитываются с диска при каждой отправке модели.
В отличие от `system-prompt.md`, они ещё и переформатируются: плейсхолдеры
заполняются кодом перед отправкой.

| Файл | Переменные (плейсхолдеры) |
|---|---|
| `user-message.md` | — |
| `last-iteration-message.md` | — |
| `wake-up-message.md` | — |
| `sleep-warning.md` | `{remaining}` — сколько итераций осталось до сна, с правильной формой слова («10 итераций», «1 итерацию»); `{memory_note}` — формируется кодом по состоянию памяти: свежая — «Проверь, что в памяти есть итог и следующий шаг.», устаревшая — «Память не отражает последние действия — обнови её сейчас.» |
| `repeat-alert.md` | `{streak}` — сколько итераций подряд повторяется, с правильной формой слова; `{examples}` — до 3 примеров вида `имя(аргументы)` |

Правила шаблонов:

- динамические части — плейсхолдеры вида `{имя}` (заполняются кодом перед отправкой);
- литеральные фигурные скобки удваиваются: `{{` и `}}`;
- отсутствующий, пустой или битый (недопустимый плейсхолдер) файл
  откатывается к дефолтному файлу — агент не падает из-за ошибки в
  пользовательском файле.

Дефолтные тексты — одна-две короткие фразы. Полный контракт (порядок
сообщений, fallback-поведение, допустимые плейсхолдеры) описан в docstring
`prompts_messages.py`.

## Что не настраивается

Заглушки восстановления истории — сбойная итерация и потерянный
tool-результат — внутренний протокол: они хранятся в коде
(`INTERNAL_MESSAGES` в `prompts_messages.py`) и в папке агента не создаются.
