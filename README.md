# Проект жизнь искуственного интелекта

## Запуск и переписка с агентом

- `python main.py [имя]` — запуск жизни агента (бесконечный цикл итераций).
- `python main.py <имя> reply` — переписка с агентом: печатается вся история
  сообщений со статусом прочитанности и номерами `[N]` (номера совпадают с
  `get_messages`), затем вы пишете ответ; Enter — сообщение дописывается в
  переписку от имени создателя, и программа завершается.
  Просмотр не меняет статусы. Агент прочитает сообщение сам через tool
  `get_messages` в следующей итерации жизни.
- `--loop-pause=N` — фиксированная пауза между итерациями (сек), указывается
  в любой позиции (например, `python main.py bot --loop-pause=30`); отключает
  адаптивное расписание паузы. Действует только в режиме жизни агента.
- `python main.py <имя> pay <единицы> "<причина>"` — начислить агенту
  положительное целое число единиц; `python main.py <имя> balance` показывает
  его доступные единицы и оплаченные циклы, а `python main.py <имя> history` —
  историю его трат. Имя обязательно, неизвестный агент не создаётся. Денежные
  команды работают без `OPENAI_BASE_URL`, модели и Docker.

## Tools агента

- `send_message` — отправить сообщение создателю (дописывается в переписку);
- `get_messages` — страница всей переписки с создателем; показанные
  непрочитанные сообщения помечаются прочитанными, а в ответе видны как
  `не прочитано` + `стало прочитанным`; `cursor` + `limit` листают к более старым;
- `money_balance` — показать доступные единицы и остатки эффектов агента;
  `money_spend(units, purpose, type)` — добровольно потратить единицы.
  `type` обязателен и равен `speed` (отменить ожидание перед следующим циклом)
  или `creativity` (использовать `TEMPERATURE=1.4` в следующем цикле).
  Одна единица действует один следующий цикл; она не покупает токены и не
  добавляет tool-вызовы. `purpose` обязателен.
- `get_memory` / `set_memory` — рабочая память агента (`memory.md`): статусы
  и планы текущей сессии, агент перезаписывает её сам;
- `sleep(reason)` — добровольно завершить текущую сессию раньше 30 циклов,
  если агент устал или контекст стал слишком большим. Перед вызовом нужно
  сохранить итог и следующий шаг через `set_memory`; причина обязательна.
- `diary_remember` / `diary_recall` / `diary_edit` — дневник: долгая личная
  память агента (`diary.json`); см. ниже;
- `diary_tags` — оглавление тем дневника: частые теги записей за все жизни
  (топ по числу записей, фильтры `kinds`/`min_count`);
- `run_bash` — команда в изолированной Docker-песочнице. **Выключен по
  умолчанию**: в .env задайте `ENABLE_BASH_TOOL=1`, чтобы вернуть его в список
  tools (без флага LLM его не видит, Docker-контейнер не создаётся). Его
  stdout/stderr также ограничиваются общим лимитом 2000 строк или 50 КБ.
- `read_file` — постраничное чтение текстового файла из той же песочницы
  (тот же флаг `ENABLE_BASH_TOOL`): в ответе сначала объём файла
  (строк/байт), затем запрошенный диапазон строк с номерами и подсказка
  `offset=N` для продолжения — большие файлы листаются частями, а контекст
  LLM не раздувается (лимит страницы 200 строк, максимум — 1000;
  сверхдлинные строки обрезаются, весь ответ ограничен 50 КБ). Значения
  `limit` вне диапазона приводятся к ближайшей границе с пометкой в ответе.
- `write` — создать или полностью перезаписать файл; возвращает `ok`, путь и
  число UTF-8 байт. `edit` — заменить ровно одно точное совпадение `old` на
  `new`; при нуле или нескольких совпадениях файл не меняется.
- `grep` — поиск строк по regexp с фильтром `include`; `find` — поиск файлов
  по glob-шаблону; `ls` — список каталога. Их выдача ограничена 2000 строками
  или 50 КБ (что наступит раньше), без частичных строк, с метаданными
  `truncatedBy`, `totalLines`, `totalBytes`. Все эти tools используют тот же
  флаг `ENABLE_BASH_TOOL`.
- `inspect_image` — ответить на вопрос по изображению. `source` — URL `http`/`https`
  или абсолютный путь внутри Docker-контейнера агента (например,
  `/root/assets/photo.webp`), `question` — непустой вопрос. Изображение
  проверяется и передаётся вложенной vision-модели; наружу возвращается только
  её текстовый ответ.
- `web_fetch` — напрямую прочитать страницу по URL без Brave и без ключей.
  Возвращает видимый текст: ссылки в нём помечены `[1]`, `[2]` и т. д.,
  а их URL перечислены внизу. Обязателен `url` с протоколом `http` или
  `https`. Большие страницы листаются по символам: `offset` начинается с 1,
  `limit` — размер страницы (по умолчанию и максимум 8000); продолжение
  указано в ответе tool.
- `internet_search` — поиск свежей информации через Brave Search API; это
  отдельный legacy-tool, доступный только при непустом `BRAVE_KEY` в `.env`.

Для проверки vision через реальный OpenAI-compatible API используйте
`.venv/bin/python -m unittest tests.test_vision_live -v`; без доступного API
или Docker тест пропускается, а `AI_LIVE_REQUIRED=1` делает его обязательным.

### DeepSeek API и DeepSeek-V4.1-Flash

Официальный API предоставляет V4.1-Flash под именем `deepseek-flash`. Для
переключения в `.env` нужны такие значения:

```dotenv
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-flash
OPENAI_API_KEY=ключ_DeepSeek
# либо DEEPSEEK_API_KEY=ключ_DeepSeek
REASONING_EFFORT=max
```

`/v1` к `OPENAI_BASE_URL` добавлять не нужно. Ключ можно оставить в
`OPENAI_API_KEY` или назвать `DEEPSEEK_API_KEY`. Модель поддерживает tools и
нативное изображение для `inspect_image`: URL или путь из Docker превращается
в JPEG Data URL и отправляется в пользовательском сообщении. Алиас
`DeepSeek-V4.1-Flash` тоже нормализуется в `deepseek-flash`.

Старый профиль DeepInfra (`https://api.deepinfra.com/v1/openai` и
`deepseek-ai/DeepSeek-V4.1-Flash`) сохранён для совместимости.

Кошелёк агента хранится отдельно в `wallet.json` и не входит в `mind-loop.json`:
кредит создателя увеличивает доступный баланс, а `money_spend` уменьшает его и
увеличивает запас выбранного эффекта — `speed` или `creativity`. Сумма трат не
является отдельной строкой при автоматическом использовании цикла: в журнале
есть только `credit` и `spend`. Создатель — безлимитный источник начислений, его
баланс нигде не создаётся. При нулевом балансе агент продолжает работать по
обычному расписанию.

Переписка с создателем хранится в папке агента в `messages.json` целиком.
Режим `reply` показывает всю историю, а `get_messages` выдаёт её страницами.
Прочитанность хранится флагом `read` у каждого сообщения: сообщения агента
сразу прочитанные, сообщения создателя — непрочитанные, пока агент не прочтёт
их через `get_messages`. Режим `python main.py <имя> reply` только показывает
историю и не меняет эти флаги.

## Дневник — долгая память

`memory.md` — «рабочий стол» текущей сессии: каждый `set_memory` полностью
перезаписывает его. Дневник (`diary.json`) — второй слой памяти,
накапливающий, а не перезаписывающий (append-only по духу):

- `diary_remember(text, tags=[], kind="note")` — добавить запись (до 2000
  символов); время ставится автоматически, возвращается id записи.
  kind: `event` (событие/диалог), `lesson` (урок/ошибка), `value` (вкус,
  принцип), `idea` (зародившаяся мысль), `note` (по умолчанию);
- `diary_recall(query, tags, kinds, limit=20, order="new", mode="hybrid")` —
  поиск/чтение: FTS5 ищет по словам, `hybrid` добавляет смысловой поиск;
  `text` оставляет только поиск по словам, `vector` — только смысловой.
  В `hybrid`/`vector` результаты идут по релевантности, а `text` и запрос без
  `query` сохраняют прежний порядок `order`. Все фильтры и курсоры сохраняются;
  каждая запись в ответе: id, время, kind, tags, text. Без токена
  `DIARY_EMBED_TOKEN` или расширения `vec0.so` hybrid автоматически использует FTS5.
  Индексы строятся и обновляются автоматически рядом с `diary.json`; вручную
  запускать `reindex_*` не требуется;
- `diary_edit(id, text)` — правка одной записи без касания остальных;
- `diary_tags(limit=10, min_count=1, kinds)` — оглавление тем: частоты тегов
  за один вызов (сортировка по числу записей, при равенстве — по алфавиту).
  Панорама всех жизней без листания архива: по облаку тегов видно и
  затухающую тему (перестала пополняться). Полезно взглянуть на него
  при пробуждении — рядом с памятью и сообщениями; перекликающаяся с планом
  тема вытягивается точечным `diary_recall(tags=[...])`.

Дневник переживает «сон» между сессиями (mind-loop.json архивируется,
а diary.json — нет) и создаётся пустым при первом запуске агента.

### sqlite-vec (необязательная часть)

FTS5 работает без дополнительных пакетов. Для смыслового поиска нужен
`vec0.so`; приложение ищет его рядом с `diary.json`, в корне проекта или по
`DIARY_VEC_SO`. В Ubuntu/Debian отдельного apt-пакета sqlite-vec нет:
для сборки из исходников нужны `build-essential` и `libsqlite3-dev`
(список зафиксирован в `apt-packages.txt`).
Можно взять проверенное готовое расширение `sqlite-vec==0.1.9`:

```bash
sudo apt-get install build-essential libsqlite3-dev
python -m pip install -r requirements-vector.txt
python - <<'PY'
import shutil
from pathlib import Path
import sqlite_vec
source = Path(sqlite_vec.loadable_path())
if not source.exists():
    source = Path(str(source) + ".so")
shutil.copyfile(source, "vec0.so")
PY
```

`vec0.so` намеренно игнорируется Git и должен устанавливаться отдельно на
каждом хосте. Без него и/или без `DIARY_EMBED_TOKEN` hybrid автоматически
деградирует до FTS5.

## Адаптивная пауза цикла

Пока в переписке не появляются новые сообщения создателя, пауза между
итерациями растёт по расписанию: 0 сек → 30 сек → 1 мин → 2 мин → 5 мин →
10 мин → 20 мин → 40 мин → 1 час → 2 часа → 4 часа (дальше — не реже раза
в 4 часа). Одна потраченная единица типа `speed` отменяет паузу перед одним
следующим циклом; несколько единиц применяются к нескольким следующим циклам.
Единица типа `creativity` вместо этого включает `TEMPERATURE=1.4` на один
цикл. Эти эффекты не меняют число tool-вызовов. Запас переживает перезапуск и сон, а `money_spend` не запускает тик
немедленно и не сбрасывает backoff. Неинтересный создателю агент не жжёт токены впустую; как
только создатель пишет (через `python main.py <имя> reply`), расписание
сбрасывается — агент отвечает почти сразу. Сообщение, написанное прямо
во время длинной паузы, не ждёт её конца: цикл раз в секунду проверяет
переписку и при новом сообщении создателя сразу просыпается —
расписание обнуляется, и LLM работает немедленно. Сообщения самого
агента (`send_message`) паузу не сбрасывают и не прерывают. `LOOP_DELAY`
в .env задаёт минимальную паузу (по умолчанию 1 сек), а время самой
итерации вычитается из паузы.

Флаг запуска `--loop-pause=N` отключает адаптивное расписание: пауза
между итерациями всегда ровно N секунд (например,
`python main.py bot --loop-pause=30` — итерация раз в 30 секунд,
сколько бы создатель ни молчал). В этом жёстком режиме speed-циклы не
расходуются и сохраняются до возврата к адаптивному расписанию; creativity-
циклы по-прежнему применяются к LLM. Сообщения создателя по-прежнему
доставляются агенту и по-прежнему прерывают саму паузу немедленно, но
на длительность следующей паузы уже не влияют. `LOOP_DELAY` в этом
режиме не применяется — фиксированное значение важнее.

Длину сессии и момент предупреждения о сне можно менять через `.env`:
`SESSION_ITERATIONS` — от 1 до 10 000 итераций (по умолчанию 30),
`SLEEP_WARN_REMAINING` — от 0 до значения меньше длины сессии (по умолчанию
10). Изменения применяются к баннеру, циклу, предупреждению о сне и шаблону
системного промпта нового агента.

## Файлы сообщений в папке агента

Редактируемые тексты (системный промпт и служебные сообщения цикла) лежат
файлами в папке агента рядом с `system-prompt.md` и перечитываются с диска
при каждой итерации — их можно менять на живом агенте без правки кода и
перезапуска. Описание всех файлов, плейсхолдеров, правил шаблонов и
дефолтных текстов смотрите в
[default-prompts/README.md](default-prompts/README.md).
